Applies when: the diff touches `package.json`, `pnpm-lock.yaml`,
`pnpm-workspace.yaml`, environment handling, `.mcp.json`, `.codex/`,
`.claude/`, `AGENTS.md`, skill layout, Storybook, lint/test/build scripts,
ports, or tool configuration.

# Developer experience

Check that a clean clone and both supported harnesses can follow the changed
contract.

- Manifest, lockfile, allowed build scripts, and installed package contents
  agree.
- Scripts referenced by documentation, hooks, skills, and tests exist and
  have the stated mutating or non-mutating behavior.
- Baseline verification exits deterministically; it does not start a watch
  process, rewrite files, or require Storybook/E2E when the change does not.
- `.mcp.json` and `.codex/config.toml` expose equivalent server names,
  transports, URLs, commands, arguments, and environment.
- `AGENTS.md` is canonical and `CLAUDE.md` remains a Git symlink to it.
- Shared skills live under `.agents/skills`; Claude links resolve to them.
- Commands and rules directories remain absent.
- Manual-only skills disable implicit invocation in both Claude frontmatter
  and Codex metadata.
- Package-managed design-system skills remain ignored and generated by the
  dependency rather than edited or committed.
- New required tools are pinned or clearly optional, and a clean install
  exposes the runtime path used by the skill.
- No user name, home path, private workspace metadata, token, or local-only
  artifact enters tracked files.

When a dependency changes, inspect the installed exports and relevant release
surface instead of trusting a successful lockfile update.
